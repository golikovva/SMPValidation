# Дисковый кэш интерполяции

Кэш сохраняет веса ESMPy между исходной и целевой сетками. При следующем создании
`Dataset` с той же парой сеток веса загружаются с диска. По умолчанию кэш выключен:
`interpolation_cache_dir=None` сохраняет прежний способ вычисления весов в памяти.

## Пример для NEMO

```python
from pathlib import Path

from libs.validation.grid import BarentsKaraGrid
from libs.validation.datasets.nemo import NemoSicDataset

dataset = NemoSicDataset(
    path=Path("/data/nemo"),  # Каталог с файлами NEMO в структуре run_*.
    dst_grid=BarentsKaraGrid(resolution=10.0),
    average_times=[0],
    interpolation_cache_dir=Path("cache/interpolation"),
)

# Работа с dataset, как обычно.
# После последнего обращения к интерполятору освободите оператор ESMF:
dataset.interpolator.destroy()
```

Каталог создаётся автоматически. При повторном запуске этого примера используется
тот же файл весов. Если `dst_grid=None`, интерполятор и кэш не создаются.

Для существующих объектов сеток можно включить кэш напрямую:

```python
from libs.validation.interpolator import Interpolator

interpolator = Interpolator(src_grid, dst_grid)
try:
    interpolator.initialize(cache_dir="cache/interpolation")
    result = interpolator(source_field)
finally:
    interpolator.destroy()
```

## Что хранится и когда пересчитывается

- Один файл `<sha256>.nc` содержит веса и служебные атрибуты проверки кэша.
- Ключ учитывает форму и порядок обеих сеток, координаты центров и углов ячеек,
  топологию ESMF, метод и параметры интерполяции, версии ESMPy/ESMF и формат кэша.
- Метод по-прежнему выбирается по средней площади ячеек: `CONSERVE`, если исходные
  ячейки меньше целевых, иначе `BILINEAR`.
- Значения поля, дата, имя датасета и путь к исходным данным в ключ не входят.
  Поэтому разные поля и файлы с одинаковой геометрией могут использовать одни веса.
- Сначала записывается отдельный временный файл, затем готовый файл публикуется
  атомарно. Параллельные независимые процессы могут повторить расчёт при первом
  обращении; частично записанный файл не становится рабочим кэшем.

Маска доступной области `dst_region` восстанавливается явным пробным применением
оператора после его создания или загрузки. Точки вне покрытия остаются `NaN`.
Кэш не сохраняет результаты интерполяции или маску пропусков конкретного поля.

## Ограничения и обслуживание

- Нужны рабочие ESMPy/ESMF с поддержкой NetCDF и Python-пакет `netCDF4`.
- Кэш поддерживает последовательный ESMF. При нескольких ESMF-процессах или
  пользовательских ESMF-масках/площадях выполняется обычный расчёт с предупреждением.
- Если каталог недоступен, файл повреждён или его служебные атрибуты не совпали,
  интерполяция продолжает работать с пересчётом весов. Ошибки самой геометрии
  или интерполяции по-прежнему приводят к исключению.
- Сообщения о загрузке и сохранении доступны на уровне `INFO`, об отказе кэша —
  `WARNING` в стандартном `logging`.
- Старые файлы автоматически не удаляются. Ненужные веса можно удалить, когда
  они не используются: при следующем запуске они будут вычислены заново.

Ускоряется подготовка оператора. Поиск и чтение файлов `Dataset`, создание сеток,
вычисление площадей, хэширование координат и применение весов к каждому полю
остаются необходимыми. На маленьких сетках чтение файла может оказаться дороже
повторного расчёта; универсального коэффициента ускорения нет.

## Проверка и замер времени

Из корня репозитория в научном окружении проекта:

```text
python -B -m unittest discover -s tests -p "test_interpolator_cache_esmpy.py" -v
python -B benchmarks/benchmark_interpolation_cache.py --fine-size 240 --coarse-size 120 --repeats 3 --applications 10
```

Интеграционные тесты используют настоящие ESMPy и NetCDF. Для обоих методов они
сравнивают значения и маски `NaN` без кэша, при первой записи и при повторной
загрузке, проверяют частично и полностью непересекающиеся сетки и загрузку в новом
Python-процессе с запретом пересчёта весов. Для полностью непересекающихся сеток
допускается расчёт в памяти, если ESMF не поддерживает файл с нулевым числом весов.
При отсутствии ESMPy или `netCDF4` тесты явно пропускаются.

Бенчмарк использует те же синтетические сетки, без модельных данных. Он отдельно
измеряет `initialize()` и вызов интерполятора, проверяет совпадение результатов
и выводит JSON с версиями библиотек, размерами сеток, отдельными замерами,
медианами, размером файла весов и отношением времени подготовки без кэша к времени
повторной загрузки. В повторном замере пересчёт весов запрещён: отказ загрузки
завершает бенчмарк ошибкой. Построение самих сеток в эти времена не входит.

Каждый повтор использует новый каталог для первого расчёта и тот же каталог для
повторной загрузки. Временные файлы удаляются после замера. Параметр
`--cache-dir PATH` выбирает родительский каталог на нужном диске; существующие
файлы в нём не меняются. Требуется `fine-size >= 2 * coarse-size`, чтобы оба метода
стабильно выбирались по площади ячеек. Замеры зависят от оборудования, диска и
файлового кэша ОС; фиксированного порога скорости в тестах нет.
