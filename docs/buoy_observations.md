# Наблюдения буёв: толщина, дрейф, SST и SSS

Пакет `libs.validation.datasets.buoy` объединяет наблюдения из разных источников. Он читает готовые толщину льда и снега из `SIMBA_icethick_all/datasets` и `simb/CRREL`, позиции IABP из `itp_data/2023/2023`, поверхностные температуру и солёность UpTempO и AOTD. По запросу он вычисляет дрейф из исходных траекторий буёв. Результат сохраняет отдельные буи или профили и их координаты; привязки к сетке здесь нет.

## Пример

Пути ниже указаны относительно корня проекта. Для другого рабочего каталога передайте абсолютные пути.

```python
from libs.validation.datasets.buoy import (
    BuoyObservationDataset,
    CrrelNetCDFSource,
    SimbaTabSource,
)

sources = [
    SimbaTabSource("SIMBA_icethick_all/datasets"),
    CrrelNetCDFSource("simb/CRREL"),
]
ds = BuoyObservationDataset(
    sources,
    variables=("ice_thickness", "snow_thickness"),
    T=4,
    step="6h",
    time_method="nearest",
    tolerance="3h",
    coord_tolerance="12h",
    coverage="partial",
)

# Четыре запрошенных момента с шагом 6 часов.
batch = ds["2012-08-20T18:00:00"]

# Произвольная общая ось времени использует ту же политику nearest.
selected = ds.at(["2012-08-20T18:00:00", "2012-08-21T06:00:00"])
window = ds.between("2012-08-20", "2012-08-22", step="6h")

ice = batch.var_names.index("ice_thickness")
usable = batch.coord_valid & batch.valid[..., ice]
ice_values = batch.variables[..., ice][usable]
ice_coords = batch.coords[usable]
ice_observed_at = batch.value_times[..., ice][usable]
positions_observed_at = batch.coord_times[usable]

# Индекс выбирает начало из ds.times; не означает порядковый час.
first_window = ds[0]
native = ds.read_native(ds.buoy_ids[0])
```

По умолчанию запрашиваются обе переменные, `T=1`, `step="1h"`, `time_method="exact"`, `tolerance=None`, `coord_tolerance=None`, `coverage="partial"`. При `exact` нужны точные временные совпадения; пример явно включает `nearest` и задаёт оба допуска. Если `coord_tolerance` не указан, для координат используется `tolerance`. `start_times` позволяет задать собственные начала окон вместо исходных кандидатов `ds.times`.

Для окна с обязательной толщиной льда и необязательным снегом:

```python
complete_ds = BuoyObservationDataset(
    sources,
    variables=("ice_thickness", "snow_thickness"),
    required_variables=("ice_thickness",),
    T=4,
    step="6h",
    time_method="nearest",
    tolerance="3h",
    coord_tolerance="12h",
    coverage="complete",
)
complete_batch = complete_ds["2012-08-20T18:00:00"]
```

## Поверхностные температура и солёность

Для обоих источников нужно явно указать `max_surface_depth` в метрах: конечное неотрицательное число. Граница включается. Например, `5` допускает значения на глубинах от 0 до 5 м; `10` расширяет этот диапазон до 10 м. Это правило отбора измерений, а не вертикальная интерполяция к заданной глубине.

```python
from libs.validation.datasets.buoy import (
    AotdNetCDFSource,
    BuoyObservationDataset,
    UpTempOTabSource,
)

surface_ds = BuoyObservationDataset(
    [
        UpTempOTabSource("UpTempO", max_surface_depth=5),
        AotdNetCDFSource(
            "thermohaline_ds/AOTD2023.nc",
            max_surface_depth=5,
            time_units_override="days since 1980-01-01 00:00:00",
        ),
    ],
    variables=("sst", "sss"),
    T=4,
    step="6h",
    time_method="nearest",
    tolerance="3h",
    coord_tolerance="3h",
    coverage="partial",
)
surface_batch = surface_ds["2023-08-01T00:00:00"]

sst = surface_batch.var_names.index("sst")
usable = surface_batch.coord_valid & surface_batch.valid[..., sst]
temperature_degC = surface_batch.variables[..., sst][usable]
temperature_depth_m = surface_batch.depths[..., sst][usable]
temperature_observed_at = surface_batch.value_times[..., sst][usable]

sss = surface_batch.var_names.index("sss")
salinity_psu = surface_batch.variables[..., sss]
salinity_depth_m = surface_batch.depths[..., sss]
```

`UpTempOTabSource(folder, *, max_surface_depth, pattern="*.dat")` использует готовые поверхностные поля продукта. Измерение с неизвестной, отрицательной или превышающей предел глубиной не проходит отбор. `AotdNetCDFSource(path, *, max_surface_depth, time_units_override=None)` независимо для температуры и солёности выбирает самое мелкое допустимое конечное значение профиля. Поэтому SST и SSS одного профиля могут иметь разные глубины и маски.

В опубликованном `AOTD2023.nc` атрибут времени содержит `since 1980-01-01 00:00:00`, но не указывает единицу. Пример явно принимает дни через `time_units_override`; адаптер не угадывает их по имени файла или величине чисел. Исходное описание и применённое переопределение сохраняются в метаданных. Для файлов с корректной единицей времени переопределение не требуется.

При `coverage="partial"` достаточно координат и одного из выбранных поверхностных значений. Для пары SST/SSS во всех запрошенных моментах используйте `coverage="complete"`; для обязательной температуры и необязательной солёности — `required_variables=("sst",)`.

## Дрейф IABP

Для любой переменной дрейфа нужно явно задать положительный `drift_max_gap`: максимально допустимое время между двумя исходными позициями. Это ограничение интервала измерения, а не шаг выходной оси и не допуск `nearest`.

```python
from libs.validation.datasets.buoy import BuoyObservationDataset, IabpTabSource

drift_ds = BuoyObservationDataset(
    [IabpTabSource("itp_data/2023/2023")],
    variables=("drift_speed", "drift_eastward", "drift_northward"),
    drift_max_gap="6h",
    drift_max_speed=100.0,  # cm/s; это значение используется по умолчанию
    T=24,
    step="1h",
    time_method="nearest",
    tolerance="5min",
    coord_tolerance="5min",
    coverage="partial",
)
drift_batch = drift_ds["2023-08-01T00:00:00"]

speed_index = drift_batch.var_names.index("drift_speed")
support = drift_batch.drift_support
usable = support.valid & drift_batch.valid[..., speed_index]
speed_cm_s = drift_batch.variables[..., speed_index][usable]
segment_starts = support.coords[..., 0, :][usable]
segment_ends = support.coords[..., 1, :][usable]
segment_start_times = support.datetimes[..., 0][usable]
segment_end_times = support.datetimes[..., 1][usable]

# Нормализованные исходные позиции, без производных скоростей.
native = drift_ds.read_native(drift_ds.buoy_ids[0])
position_times = native.positions.datetimes
positions = native.positions.coords
```

`drift_speed`, `drift_eastward` и `drift_northward` выражены в **cm/s (см/с)**. Восточная и северная компоненты вычисляются по расстоянию и прямому азимуту геодезической WGS84 в локальных направлениях первого конца участка.

Параметр `drift_max_speed=100.0` ограничивает **модуль скорости**, а не каждую компоненту отдельно. Значение должно быть конечным положительным числом в cm/s; `None` явно отключает этот фильтр. Участок со скоростью **строго больше 100 cm/s** по умолчанию недействителен; ровно 100 cm/s допускается. При превышении порога одновременно маскируются `drift_speed`, `drift_eastward`, `drift_northward` и `drift_support`, поэтому набор компонент всегда относится к одному и тому же пригодному участку. Толщина, температура и солёность этим фильтром не изменяются.

Скорость относится к участку `t0 → t1` и записывается с временной меткой **`t0`**. Используется действительное `dt = t1 - t0` исходных позиций. Сначала разрешаются дубликаты и вычисляются native-участки, затем к их началам применяется `exact` или `nearest`. Поэтому изменение `step` не пересчитывает скорости, а запрос с `T=1` может вернуть готовую скорость участка.

Участок недействителен при пропуске любого конца, неположительном `dt`, превышении `drift_max_gap` или `drift_max_speed`; последняя исходная позиция без следующей также не даёт скорости. Пропущенная позиция разрывает соседние участки: её нельзя удалить и соединить оставшиеся точки молча. Повторные сообщения об одной фиксации объединяются по её времени; разные моменты с одинаковыми координатами дают допустимую нулевую скорость. Неопределённость дрейфа остаётся `NaN`: она не оценивается без данных о погрешности позиций.

Проверка скорости выполняется на исходных участках до `exact`/`nearest`. Начало отбракованного участка сохраняется как временной барьер: если оно выбрано при сопоставлении, результат остаётся пропуском. `nearest` не подменяет его другим допустимым участком внутри допуска. Поэтому QC нельзя обойти увеличением `tolerance`, а изменение выходного `step` не меняет решение об исходном участке.

Для включённого в batch буя краткая диагностика доступна в `batch.metadata[bid]["drift"]`: `drift_max_speed_cm_s` хранит порог либо `None`, `speed_exceeded_segments` — число исходных участков, отклонённых по скорости. Эти счётчики описывают исходную траекторию буя, а не только текущее выходное окно.

Подробности отклонённых по скорости участков запрашиваются отдельно:

```python
# Вся исходная траектория одного буя; можно проверить и буй, не попавший в batch.
rejected = drift_ds.read_drift_diagnostics(drift_ds.buoy_ids[0])
# Без аргумента — отклонённые участки всех буёв этого dataset.
all_rejected = drift_ds.read_drift_diagnostics()

for segment in rejected:
    print(segment["buoy_id"], segment["t0"], segment["t1"],
          segment["speed_cm_s"], segment["limit_cm_s"])
```

Каждый элемент списка содержит `buoy_id`, `t0`, `t1`, `coords0`, `coords1`, `dt_seconds`, `distance_m`, `speed_cm_s`, `kind="drift_speed_exceeded"` и `limit_cm_s`. Координаты задаются в порядке `[lat, lon]`; времена и расстояние позволяют проверить причину превышения. Метод возвращает независимую копию списка. Полные списки не включаются в метаданные batch и последующих полей метрик, чтобы не копировать историю отбраковки в каждое окно валидации.

При изменении порога создайте `BuoyObservationDataset` заново с новым `drift_max_speed` и повторите валидацию: исходные участки проверяются при подготовке dataset. Уже вычисленные результаты и ранее сохранённые pickle автоматически не пересчитываются. При `drift_max_speed=None` список отклонений по скорости пуст; остальные проверки координат и `drift_max_gap` остаются в силе. Если переменные дрейфа вообще не запрошены, `read_drift_diagnostics` также возвращает пустой список.

## Совместный запрос толщины и дрейфа

```python
from libs.validation.datasets.buoy import (
    BuoyObservationDataset, CrrelNetCDFSource, IabpTabSource, SimbaTabSource,
)

mixed_ds = BuoyObservationDataset(
    [
        SimbaTabSource("SIMBA_icethick_all/datasets"),
        CrrelNetCDFSource("simb/CRREL"),
        IabpTabSource("itp_data/2023/2023"),
    ],
    variables=("ice_thickness", "snow_thickness", "drift_speed"),
    required_variables=("drift_speed",),
    drift_max_gap="6h",
    T=4,
    step="6h",
    time_method="nearest",
    tolerance="3h",
    coord_tolerance="3h",
    coverage="partial",
)
mixed_batch = mixed_ds["2023-08-01T00:00:00"]
```

Здесь толщина необязательна: IABP может участвовать с дрейфом и `NaN` в колонках толщины. Если `required_variables` не указан, все выбранные переменные считаются требуемыми; при `coverage="complete"` буй без толщины не пройдёт такой запрос.

## Контракт результата

`BuoyBatch` использует единственный порядок осей:

| Поле | Форма | Смысл |
| --- | --- | --- |
| `bids` | `(N,)` | Идентификаторы буёв или отдельных профилей с префиксом источника |
| `coords` | `(N, T, 2)` | Широта и долгота, `float32` |
| `datetimes` | `(T,)` | Запрошенное время, `datetime64[ns]` |
| `variables` | `(N, T, V)` | Значения переменных, `float32` |
| `coord_valid` | `(N, T)` | Доступность пары координат |
| `valid` | `(N, T, V)` | Доступность каждого значения |
| `coord_times` | `(N, T)` | Исходное время выбранной позиции |
| `value_times` | `(N, T, V)` | Исходное время выбранного измерения |
| `uncertainty` | `(N, T, V)` | Опубликованная неопределённость, если доступна |
| `depths` | `(N, T, V)` | Глубина выбранного измерения в метрах, `float32` |

Порядок переменных задаётся явно и описывается `var_names` и `units`; `metadata` содержит дополнительные сведения об источниках и обработке. Толщина льда и снега выражается в метрах, дрейф — в cm/s (см/с), `sst` — в `degC`, `sss` — в `psu`. Отсутствующие или признанные недействительными значения представлены `NaN`, отсутствующее исходное время — `NaT`. Отсутствие одного измерения само по себе не превращает остальные значения в пропуски. Неизвестная неопределённость обозначается `NaN`, а не нулём.

Поле `depths` присутствует в каждом batch. Для SST и SSS оно относится к тому же исходному измерению, что `variables` и `value_times`: при `nearest` глубина выбирается вместе со значением, без отдельного поиска по времени. Для толщины, дрейфа и неизвестной глубины используется `NaN`. Глубины SST и SSS могут различаться. В `batch[bid]` форма `depths` становится `(T, V)`; при пустом результате сохраняется форма `(0, T, V)`.

При запросе дрейфа `drift_support` описывает пару исходных позиций, по которой получено значение:

| Поле | Форма в batch | Смысл |
| --- | --- | --- |
| `drift_support.coords` | `(N, T, 2, 2)` | Два конца участка, каждый `[lat, lon]`, `float64` |
| `drift_support.datetimes` | `(N, T, 2)` | Исходные времена `t0` и `t1`, `datetime64[ns]` |
| `drift_support.valid` | `(N, T)` | Доступность выбранного участка |

Одна пара описывает все запрошенные компоненты дрейфа; их `value_times` содержат `t0`. При обращении `batch[bid]` ось `N` убирается также из `drift_support`. Без переменных дрейфа поле равно `None`; пустой результат запроса дрейфа содержит support с нулевой осью `N`.

Общие `coords` и `coord_times` выбираются независимо по времени запроса и могут отличаться от начала участка дрейфа. Для анализа участка или сопоставления его скорости с моделью используйте `drift_support`. Правила `coverage` по-прежнему проверяют общую `coord_valid`; наличие support само по себе не заменяет эту проверку.

Одинаковые локальные обозначения из разных источников остаются разными идентификаторами: автоматического объединения физических буёв между источниками нет. Совпадающие дубликаты не увеличивают число наблюдений. Противоречащие друг другу дубликаты помечаются как недействительные и сопровождаются диагностикой; порядок файлов не определяет, какое значение победит.

## Время и покрытие

Все `datetime64` трактуются как UTC. Время без указанного часового пояса также считается UTC. Выходная ось `datetimes` содержит время запроса, поэтому её нельзя использовать вместо фактического времени выбранного измерения.

Для скалярных измерений и координат сопоставление `nearest` выбирает ближайшее конечное значение в пределах допуска; при одинаковом расстоянии выбирается более раннее. Для дрейфа сначала выбирается ближайшее начало исходного участка, включая отбракованные участки, и только затем проверяется его пригодность: недействительный участок не заменяется следующим допустимым. Координаты и каждая переменная сопоставляются по собственным исходным временным осям. Одно измерение может попасть в несколько соседних моментов запроса; новые измерения при этом не создаются. Маски показывают доступность выбранных значений, а сохранённое исходное время позволяет проверить смещение относительно запроса.

`ds.times` содержит уникальные отсортированные временные метки доступных запрошенных величин — кандидаты для начала запроса, если явно не задан `start_times`. Для дрейфа это начала допустимых исходных участков. Это не искусственная почасовая сетка и не гарантия полного покрытия следующего окна. `required_variables` позволяет отдельно указать, какие переменные участвуют в проверке покрытия; по умолчанию это все запрошенные переменные.

- `partial` включает буй, если хотя бы в одном моменте запроса есть координаты и хотя бы одна требуемая переменная.
- `complete` включает буй, если во всех моментах запроса есть координаты и все требуемые переменные.

Необязательные переменные остаются в результате с пропусками. Для включённого буя значение без доступных координат сохраняется, но соответствующая маска `coord_valid` равна `False`.

Запрос диапазона `between(start, stop)` использует полуинтервал `[start, stop)`: правая граница не включается. Пустой результат сохраняет запрошенную ось времени и набор переменных при `N = 0`.

Перед выделением массивов результата dataset проверяет временные границы пригодных наблюдений с учётом допуска `nearest`. Буи и профили, которые не могут участвовать в запросе, пропускаются заранее. Это особенно полезно для AOTD с множеством независимых профилей; отдельные `start` и `stop` в конструкторе не нужны.

`ds.buoy_ids` перечисляет доступные идентификаторы. `read_native(bid, start=None, stop=None)` возвращает нормализованные наблюдения выбранного буя или профиля без размещения на общей временной сетке и **без производного дрейфа**. Положение доступно в `native.positions`, прочитанные измерения — в `native.series`, например `native.series["ice_thickness"]` или `native.series["sst"]`. Для IABP `series` пуст: адаптер предоставляет позиции. Каждый скалярный поток имеет собственные `datetimes`, `values` и `depths`; глубины имеют форму `(J,)` и тип `float64`, а для переменных без глубины заполнены `NaN`. Временной фильтр использует `[start, stop)` и одновременно срезает значения, глубины и неопределённости. У AOTD этот метод возвращает выбранные поверхностные величины, а не полный вертикальный профиль.

## Особенности источников

SIMBA читается из файлов `*_icethick.tab` с описанием PANGAEA перед таблицей. Используются уже опубликованные значения толщины; пакет не вычисляет их из термокосы. В описании источника указано сглаживание трёхдневным скользящим средним. Опубликованные неопределённости относятся к исходному продукту: временное сопоставление не превращает их в новую оценку погрешности. Отрицательную толщину снега нельзя безусловно обнулять: источник связывает такие значения после схода снега с началом поверхностного таяния льда.

В CRREL используются основной канал толщины и соответствующие исходные наблюдения. Дополнительный канал `west` не подменяет основной и не усредняется с ним автоматически. Временные оси положения буя, толщины льда и снега могут различаться. Пара координат `(0, 0)` считается маркером отсутствующего положения именно в этом источнике. Координаты становятся `NaN`, но известная временная метка сохраняется, разрывая соседние участки дрейфа; сами измерения толщины не удаляются. Это правило не применяется к SIMBA или другим источникам.

`UpTempOTabSource` читает Level 2 ASCII-файлы с описанием колонок в заголовке. Для `sst` и `sss` используются опубликованные Sea Surface Temperature и Sea Surface Salinity вместе с соответствующими глубинами. Это значения первого пригодного датчика в воде, который может меняться при подъёме цепочки льдом; SST и SSS не обязаны относиться к одной глубине. Маркер `-999` означает пропуск. Если опубликованное поверхностное значение отсутствует или признано недействительным, адаптер не подменяет его произвольным термистором или датчиком солёности. Это сохраняет решения исходного QC: в L2 могут оставаться данные датчика, которые авторы исключили именно из SSS. Описания: [параметры UpTempO](https://psc.apl.washington.edu/UpTempO/Buoy_Parameters_2023a.php), [обработка Level 2](https://psc.apl.washington.edu/UpTempO/Level2_QC_doc_2025.php).

Глубины UpTempO являются оценками, опубликованными вместе с продуктом. Авторы вычисляют их по давлению, а при отсутствии давления в некоторых случаях используют номинальные глубины. Сохранённая глубина помогает сопоставлять данные с моделью, но не означает, что она измерена отдельным датчиком в каждой точке. Метаданные источника сохраняют сведения об обработке.

`AotdNetCDFSource` извлекает поверхностные значения из обработанных профилей AOTD. Поле `depth` задаёт стандартные уровни продукта, на которые авторы уже интерполировали измерения. Поэтому выбранная глубина AOTD описывает уровень профиля, а не обязательно положение исходного датчика. Солёность является практической; нулевая солёность сама по себе не считается пропуском. [Описание AOTD](https://www.nature.com/articles/s41597-025-05855-3).

В AOTD применяется отдельное правило для заполнения пропусков: солёность считается отсутствующей, если на том же уровне `temp = NaN`, `salt == 0` и `pres == 0`. Это сочетание исключается до выбора самого мелкого пригодного уровня; одиночный ноль солёности сохраняется.

Каждая строка профиля AOTD получает идентификатор вида `aotd:<имя файла без расширения>:<12 знаков SHA256 файла>:<исходный номер строки с нуля>`. Путь к папке в хеш не входит. Такой идентификатор обозначает профиль, а не физический буй. Последовательные строки, даже близкие по месту и времени, не объединяются в траекторию, и по ним не вычисляется дрейф. В смешанном запросе колонки дрейфа для AOTD остаются пустыми.

`IabpTabSource(folder, pattern="*.dat")` читает табличные файлы с заголовком и колонками `BuoyID`, `Year`, `DOY`, `POS_DOY` (также принимается `PosDOY`), `Lat`, `Lon`. Дрейф вычисляется из позиций; дополнительные колонки температуры и давления в этой версии не становятся выходными переменными. Это схема локального архива `itp_data/2023/2023`, а не современный IABP LEVEL1 с календарной датой и `GPSdelay` и не ежедневный `FR_*.dat` без заголовка.

`DOY` задаёт время отчёта, `POS_DOY` — время позиции. `Hour` и `Min` не добавляются к уже дробному DOY и не заменяют его. Дробные дни сохраняются без округления к целому часу: например, четыре десятичных знака соответствуют шагу записи 8.64 секунды, а не наносекундной точности наблюдения.

Около границы года адаптер рассматривает допустимые даты позиции в `Year - 1`, `Year`, `Year + 1` с учётом високосного года и выбирает ближайшую к времени отчёта. Это явно принятая эвристика адаптера, а не универсальное документированное правило IABP; её применение отражается в метаданных. Неоднозначные случаи и `POS_DOY < 1` исключаются с диагностикой. Отдельное время позиции важно: январский отчёт действительно может повторять декабрьскую фиксацию предыдущего года. Официальные описания: [Arctic Table](https://iabp.apl.uw.edu/TABLES/ArcticTable.php), [LEVEL1](https://iabp.apl.uw.edu/LEVEL1_BASIC_Download.html).

Маркеры координат `-999` и `-9999`, а также пара `(-90, -180)` в IABP становятся пропусками. Если время фиксации известно, запись с отсутствующими координатами сохраняет это время и разрывает соседние участки дрейфа. Правило для пары `(-90, -180)` относится только к IABP; общей нормализации координат других источников оно не меняет. Аналогично, правило CRREL для `(0, 0)` не переносится на IABP.

## Границы реализации

Пакет извлекает скалярные поверхностные значения из UpTempO и AOTD, но не выдаёт полные вертикальные профили и не читает термохалинные профили ITP. Он не интерполирует точки на сетку и не выполняет коллокацию с моделью. Название локальной папки `itp_data` не меняет её формат IABP. Существующие `BuoyDataset` и `BuoyLocationsDataset` сохраняют свои интерфейсы. Для будущих источников можно добавить адаптер в `buoy_adapters.py`; полный профиль потребует явного вертикального контракта. Коррекция толщины по отрицательной толщине снега не применяется автоматически.

Пакет использует NumPy, pandas, xarray, а для геодезии дрейфа — pyproj; чтение CRREL требует настроенного NetCDF backend. Обычный импорт через `libs.validation.datasets` также выполняет существующие родительские `__init__.py`, поэтому установленное окружение проекта может требовать дополнительные зависимости, включая ESMF/esmpy. Новый пакет не устраняет эти требования родительских импортов.

Прочитаны все 24 файла UpTempO (649 069 строк) и 22 319 профилей `AOTD2023.nc`.

|---|---:|---:|---:|

| UpTempO | 10 м | 235 368 | 152 138 |
| AOTD | 5 м | 19 095 | 19 095 |

Это покрытие исходных рядов, до временного сопоставления. В двух файлах UpTempO нет

в `metadata["diagnostics"]` и `diagnostic_counts`; причины могут пересекаться для
